# Principle — Review Before Trust

## Statement

Nothing new — a dependency, a skill, a plugin, a tool — is trusted by default. It is reviewed first, against a real, concrete standard, before being relied upon.

## Real Precedent in This Project

- The standing skill-review habit — every new skill or plugin checked for spawn-tool capability before being trusted, per the retired `the retired structural-compliance-enforcement-architecture-v3.md` Section 6.1.
- `[[sec-dependency-skill-supply-chain]]` — the real review performed for Cupcake before adoption (license, maintenance activity, security-research affiliation) as the standing example of what "reviewed" actually means.

## Why This Matters

Something new to this environment has not yet demonstrated it deserves trust. Assuming it's safe because it appears useful is exactly how an unvetted risk enters a system that otherwise checks everything else carefully.

## Application

Before adding any new dependency, skill, or capability to this environment, apply the same real review already used for Cupcake — not a lighter, informal check because the new thing seems small or convenient.

## Known Exceptions

None identified.
