# Global Policy Index

Binding policies governing how this operation builds Anvil.works applications. Not
guidelines — binding constraints. Check the relevant policy before starting any task that
touches its concern.

| Policy | Concern |
|---|---|
| `pol-anvil-first-development.md` | Anvil-First mandate, version control, backup protocol, dev tooling, enforcement severity |
| `pol-security-and-data-governance.md` | Vault-only secrets, mandatory RBAC, client data ownership |
| `pol-testing-and-quality.md` | Testing methodology mandate, two-backup discipline, feature signoff, RBAC verification |
| `pol-documentation-and-decisions.md` | Spec/ADR/policy/SOP distinction, when an ADR is required, staleness as failure |

Each policy states:
- **What** the policy is (the binding rule)
- **Why** it exists (the reason)
- **Where** it applies
